Schülerinnen und Schüler sehen nur die Bereiche, die laut LehrplanPLUS für ihre Klassenstufe relevant sind. Ausgeteilte Inhalte (z. B. Datenbanken) bleiben auch darunter sichtbar. Lehrkräfte können jeden Arbeitsbereich pro Klasse zusätzlich freigeben (früher nutzbar) oder sperren (ausgeblendet); gesperrte Bereiche sind für die Klasse auch über die direkte URL nicht erreichbar, andere Klassen sind nie betroffen.

## Kernfunktionen

- **Rollen und Anmeldung:** SSO über Microsoft 365 (docs/sso-m365.md) oder CSV-Import mit minimalen Daten (Vorname, Nachname, Klasse, Rolle).
- **OTP-Passwörter:** Neue Konten und Passwort-Resets erzeugen immer Einmalpasswörter nach der Satzbaulogik (Merksatz: "Apfel, Berg, Katze und Wolke" ergibt z. B. Abkw42!). Lehrkräfte können OTPs für einzelne Personen oder ganze Klassen erzeugen.
- **SQL-Werkstatt:** Lehrkräfte teilen Datenbankvorlagen an Klassen aus, mit Rechten pro Person: nur lesen, lesen und schreiben oder Tabellen anlegen. Jede Person arbeitet an ihrer eigenen Kopie, ER-Diagramme (Mermaid) und Missionen inklusive.
- **Code-Werkstatt:** Projekte anlegen, in Ordnern per Drag & Drop sortieren, von Lehrkräften an Klassen oder Einzelne austellen. Lehrkräfte sehen die Projekte ihrer Schülerinnen und Schüler in einer eigenen Liste und können sie öffnen, ansehen und bearbeiten (unterstützen beim Arbeiten); Fremdklassen bleiben ausgesperrt. Python-Programme laufen direkt im Browser (Pyodide), Java-Programme über eine eigene Java-Simulation direkt im Browser. Java-Projekte öffnen sich als IDE über die volle Seitenbreite: Die Dateien stehen in einem eigenen Fenster links (eine oder mehrere Klassen pro Datei, immer mit .java), Editor und Konsole teilen sich ein gemeinsames Fenster daneben – der Editor hervorgehoben, rechts in demselben Fenster die Konsole mit Tabs (Ausgabe, Klassen, Objektkonsole, Objekte, API-Hilfe), darüber die immer sichtbare Laufleiste (▶ 👣 ⏩ ⏹ als reine Icon-Buttons, die Erklärung erscheint beim Überfahren mit der Maus; ⏹ Stopp hält ein laufendes Programm an) und darunter die immer sichtbare Fehlerkonsole, jeweils als eigene Container. Fehler tragen Datei und Zeile plus deutsche Hilfestellung; ein Klick auf die Fehlerkarte springt direkt zur Stelle: Die richtige Datei öffnet sich im Editor, der Cursor steht in der Fehlerzeile und die Zeilennummer ist rot markiert – auch über mehrere Dateien hinweg. Die Fehlerkonsole passt sich beim Tippen live an (wie das Klassendiagramm): Neue Fehler erscheinen sofort ohne Ausführen, behobene Fehler verschwinden von selbst samt roter Markierung, und ein erfolgreicher Lauf ersetzt alles durch den grünen Erfolgshinweis. Für Datenbanken ohne Vorkenntnisse gibt es die eingebaute Klasse Datenbank: CREATE TABLE, INSERT, UPDATE, DELETE und SELECT direkt in Java (ausfuehren, abfrage, anzahl, wert, tabellen), eine Mini-SQL-Engine im Speicher des Browsers, bei jedem Lauf neu und ohne Setup. Es wird kein Code auf dem Server ausgeführt. Nach dem Ausführen bleibt das Programm lebendig: In der **Objektkonsole** erzeugen Schülerinnen und Schüler Objekte (z. B. `Auto a = new Auto("BMW");`), rufen Methoden auf (`a.fahren(100);`) und sehen Ergebnisse direkt (mit Autovervollständigung für Variablen, Klassen, Attribute und Methoden). Jedes `new` landet im **Objektdiagramm**: alle Objekte mit Namen, Klasse und aktuellen Attributwerten, Verweise zwischen Objekten inklusive – auch Objekte, die das Programm selbst in der Datei oder in einer main-Methode erzeugt hat, erscheinen dort unter ihrem Variablennamen. Eine main-Methode wird dafür bewusst nicht benötigt und kommt auch in den Startpaketen nicht mehr vor (bestehende Projekte mit main laufen weiter). Objekte lassen sich auch direkt in der Datei erzeugen: Anweisungen wie `Auto a = new Auto("BMW");` oder ganze Schleifen dürfen ohne umgebende Klasse am Datei-Ende stehen und laufen beim Ausführen mit (mehrere Klassen pro Datei sind erlaubt, auch mehrere public-Klassen; nur bei einer einzigen Klasse pro Datei muss ihr Name dem Dateinamen entsprechen). Rückgabewerte bloßer Aufrufe am Datei-Ende erscheinen als „Ergebnis: …“ in der Ausgabe. Die Java-IDE folgt dabei dem BlueJ-Prinzip: Das **Klassendiagramm** steht als eigener Tab direkt neben Editor und Konsole – live aus dem Code gelesen (UML-Boxen mit Sichtbarkeit +/−/# und Parametern), ohne dass das Programm läuft; **Vererbung wird als Pfeil gezeichnet**: Jede Unterklasse hängt mit einem Pfeil (Spitze zeigt zur Oberklasse) unter ihrer Oberklasse, bei Eltern außerhalb des Projekts (z. B. Grafik-Basisklassen) bleibt die Notiz „↳ erbt von“. Per Knopf lässt sich das Diagramm in die Diagramm-Werkstatt übernehmen. Ein Klick im Dateifenster links zeigt die gewählte Datei im Editor und setzt den Cursor hinein; das Overlay fürs Syntax-Highlighting liegt exakt deckungsgleich unter dem Text, damit der Cursor nicht verschoben wirkt. Beim Neuanlegen ist Java die Standardsprache (Python läuft weiter, ist aber vorerst ausgeblendet). Projekte erscheinen in der Übersicht nach Ordnern gruppiert als kompakte Zeilen; auch die HTML-Werkstatt zeigt ihre Seiten so, mit Ordnerliste und Drag & Drop. Der Editor zeigt **Zeilennummern** links an; Fehler aus der Fehlerkonsole markiert er dort **rot**, die beim Einzelschritt aktuelle Zeile **gelb**. Im Dateifenster links ist eine Datei mit Fehlern **rot unterlegt**, die Datei des aktuellen Einzelschritts **gelb** – auch wenn sie gerade nicht geöffnet ist. Mit **👣 Einzelschritt** läuft das Programm Anweisung für Anweisung (z. B. erst das Objekt erzeugen, dann statementweise durch die Methode) – der Editor springt dabei bei jedem Schritt automatisch zur Datei und Zeile, die als Nächstes dran ist –, mit **⏩ Weiter** der Rest bis zum Ende. Die **Auto-Formatierung** rückt den Code sauber ein: Tab rückt ein (4 Leerzeichen), Shift+Tab rückt aus, Enter übernimmt die Einrückung der vorigen Zeile, eine schließende Klammer rückt automatisch aus, und der 🧹-Button formatiert die ganze Datei. Die **Klammer-Automatik** schließt (, [ und { sofort mit Cursor dazwischen – in jedem Browser: AltGr meldet sich in Chrome als Strg+Alt, in Firefox nur als Alt, am Mac als Optionstaste, und ein zusätzlicher beforeinput-Fänger greift, selbst wenn keydown das Zeichen einmal nicht meldet; eine { am Zeilenende öffnet den Block richtig (Cursor in neue eingerückte Zeile, schließende Klammer darunter), und die selbst getippte schließende Klammer wird übersprungen statt verdoppelt. **Datentypen werden durchgesetzt:** int-Attribut mit String (und umgekehrt), falsche Parameter- und Rückgabetypen erzeugen deutsche Fehlermeldungen mit Zeile und Tipp; Unterklasse zu Oberklasse passt, fremde Klassen nicht. **Automatisches Speichern:** Jede Änderung landet ohne Speichern-Klick auf dem Server (Speichern-Button und Titel-Feld sind aus der Leiste entfallen, der Titel steht nur noch einmal im Kopf der Seite); ein dezenter Status mit Häkchen und Uhrzeit meldet sich nur, wenn gerade gespeichert wird, beim Anlegen einer neuen Datei oder Löschen wird vorher garantiert gesichert. Die **📖 API-Hilfe** öffnet auf einen Klick in einem eigenen Fenster (das beim Weiterprogrammieren offen bleibt; blockiert der Browser Popups, erscheint sie als schwebendes Fenster in der Seite) und dokumentiert kinderfreundlich alles Verwendbare: System.out, Math, String, Datenbank und die komplette Grafik-API. Das **Grafik-Fenster** (nach dem Vorbild der OnlineIDE/learnj) öffnet sich automatisch beim ersten `new World(...)` oder `new Circle(...)` in einer eigenen Zeile unterhalb der Konsole: ein XY-Feld mit Ursprung links oben, darin Circle, Ellipse, Rectangle, RoundedRectangle, Triangle, Line, Text, Polygon, Bitmap, Turtle, Group, Actor und Punkt; Figuren verschieben, drehen, färben, animieren (act-Methode), auf Tastatur und Maus reagieren, Kollisionen prüfen und eigene Klassen per `extends` von Figuren ableiten – alles direkt im Browser. Dazu die Klassenbibliothek der Online-IDE (online-ide.de) in gleicher Art und Weise: **Input** (readString/readInt/readDouble/readBoolean/readChar per Dialogfenster mit Nachfrage bei falschen Eingaben, isKeyDown), **Key** (Tasten-Konstanten wie Key.ArrowUp), **Random** (randint, randdouble, nextInt, nextDouble), **Assertions** (assertTrue/assertFalse/assertEquals/assertCodeReached/fail mit ✓-Ausgabe und deutscher Meldung bei Fehlschlag), **MathTools** (Abstände Punkt-Gerade/Strecke, Streckenschnitte, Polygon- und Kreis-Tests), **Vector2** (2D-Vektoren mit Rechnen, Drehen, Normieren), **Position** (Gitterpunkte), **Direction** (top/right/bottom/left mit getDx/getDy), **CollisionPair** (zwei zusammengestoßene Figuren), **SystemTools** (clearScreen, setSpeed/getSpeed für die act-Animation, Print-Log, Prozessorkerne), **Sound** (kurze Töne per Web-Audio: beep, click, coin, boom, laser, jump, win, lose, alarm) und **Gamepad** (Controller abfragen); als Figuren kommen **Arc** (Kreisbogen-Ring mit Innen-/Außenradius) und **Sector** (Tortenstück mit drawRadii) dazu; die eigene Klasse **Punkt** zeichnet einen kleinen gefüllten Kreis zum Markieren von Positionen: `new Punkt(x, y)` oder mit Durchmesser `new Punkt(x, y, 20)`. Bewusst offen (steht als Idee in den GitHub-Issues): Timer (bräuchte Schnittstellen/Lambdas), Sprite-Bildbibliotheken, 3D, Netzwerk, Robot/Kara/Hamster und die Abiturklassen.
- **HTML-Werkstatt:** Webseitenprojekte mit drei Ansichten: 🖌️ Gestalten (WYSIWYG komplett ohne externe Bibliotheken: Absatzart, Fett/Kursiv/Unterstrichen, Listen, Farbe, Link, Rückgängig/Wiederholen), 📝 Quelltext (mit Syntax-Highlighting) und 👁️ Vorschau (per Klick auch in neuem Fenster). HTML-Dateien lassen sich vom Computer öffnen (hochladen) und herunterladen. Zum echten Lernen erklärt die Tag-Auswahl 22 HTML-Bausteine auf Deutsch mit Mini-Beispiel; ein Lerntipp verbindet die Ansichten: Wer etwas gestaltet, schaut im Quelltext nach, welcher Tag dabei entsteht. Gespeichert wird wie gehabt auf dem Server, der Quelltext bleibt die eine Quelle der Wahrheit.
- **Syntax-Highlighting:** Alle Code-Editoren (HTML, Python, Java, SQL, Mermaid) heben Schlüsselwörter, Zeichenketten, Zahlen und Kommentare farbig hervor, live beim Tippen und in Musterlösungen. Umgesetzt als Overlay (transparente Textarea über farbigem Code), highlight.js per CDN, alles clientseitig ohne Servercode.
- **Aufgabenpool:** Aufgaben anlegen, bearbeiten (inkl. Musterlösung) und an ganze Klassen oder einzelne Personen austeilen, mit optionalem Starttermin (Datum und Uhrzeit: erst ab diesem Zeitpunkt erscheint die Aufgabe für die Klasse bzw. Person, vorher bleibt sie unsichtbar; nachträglich pro Zuweisung änderbar oder streichbar) und optionalem Abgabetermin (Datum und Uhrzeit, nachträglich änderbar oder streichbar; der Zuweisungszeitpunkt wird notiert). Zuweisungen lassen sich jederzeit einziehen, ohne die Aufgabe zu löschen; bereits abgegebene Lösungen bleiben erhalten. Pro Aufgabe einstellbar: maximale Punktzahl, Erwartungshorizont (Bewertungskriterien für die Korrektur und die KI) und eine Frist-Sperre, nach der nach dem Abgabetermin keine Abgaben mehr angenommen werden. Schülerinnen und Schüler sehen nur Aufgaben bis zu ihrer Jahrgangsstufe und erst ab dem Starttermin, geben Text-Lösungen ab (bis zum Termin beliebig oft überschreibbar, danach verspätet sofern keine Frist-Sperre aktiv) und sehen die Korrektur mit Note und Feedback; nach der Korrektur ist keine neue Abgabe mehr nötig. Die Korrekturübersicht zeigt je Aufgabe alle Abgaben mit Status (offen, abgegeben, verspätet, korrigiert) samt Musterlösung, Erwartungshorizont und Punktrahmen zum Vergleich. Dazu ein kuratierter Aufgabenkatalog mit fertigen Aufgaben passend zum LehrplanPLUS (Jahrgangsstufen 6 bis 13, filterbar nach Stufe und Typ): einzelne Aufgaben oder alle einer Jahrgangsstufe lassen sich mit einem Klick als Kopie in den eigenen Pool übernehmen (Duplikate werden übersprungen). **Austausch zwischen Lehrkräften:** Eigene Aufgaben lassen sich in den gemeinsamen Pool aller Lehrkräfte teilen (und zurückziehen); geteilte Aufgaben erscheinen dort mit Urhebername und können als individuelle Kopie übernommen und frei angepasst werden, ohne das Original zu verändern. **KI bei der Korrektur:** Jede Lehrkraft kann unter /aufgaben/ki eine eigene KI-Schnittstelle hinterlegen (Endpunkt-URL, API-Schlüssel, Modell; OpenAI-/Mistral-kompatible Chat-API oder eigener JSON-Endpunkt), die Administration zusätzlich schulweite Zugangsdaten für alle Lehrkräfte ohne eigene Angaben. Auf Klick bewertet die KI alle offenen Abgaben vor (anonymisiert mit Pseudonymen, mit Musterlösung, Punkterahmen und Erwartungshorizont als Kontext), Note-Vorschlag und Feedback erscheinen in der Korrektur als deutlich markierter Vorschlag und zählen erst, wenn die Lehrkraft sie übernommen hat. Die Roadmap mit weiteren geplanten Features steht in docs/AUFGABEN.md; die Phase-2-Ideen sind zusätzlich als GitHub-Issues #11 bis #19 angelegt. **Aufgabenbereich 2.0 (Phase 3):** Aufgaben tragen ein Themengebiet nach LehrplanPLUS (kuratiert pro Jahrgangsstufe 6 bis 13, frei ergänzbar; Informatik ist am Gymnasium Pflichtfach der Jahrgangsstufen 8 bis 10 im NTG, an der Mittelschule der 5 bis 10, an der Realschule Wahlpflichtfach ab 7). Der Aufgabenbereich lässt sich durchgängig nach Klasse filtern, was die Themengebiete auf die Stufe der Klasse kaskadiert, zusätzlich nach Jahrgangsstufe und Typ. Beim Verteilen wählt die Lehrkraft eine ganze Klasse oder mehrere einzelne Schülerinnen und Schüler gleichzeitig aus (Start- und Abgabetermin im selben Formular), und der Pool zeigt pro Zuweisung den Abgabefortschritt und alle Termine. Die Beschreibung wird im WYSIWYG formatiert (Fett, Überschriften, Listen, Code-Blöcke, Links; Whitelist-Sanitizer gegen eingeschleusten Code) und lässt sich aus der Schüler-Sicht jederzeit ein- und ausblenden. Pro Aufgabe gibt es ToDos (Vorlage der Lehrkraft, abhakbar, plus eigene ToDos der Schülerinnen und Schüler) und Materialien als Vorlagen je Aufgabentyp: Java-Starterdatei (.java), HTML-Gerüst (index.html) oder SQL-Schema (.sql) für eine aufgabeneigene Datenbank (Upload bis 512 KiB oder als Text angelegt, Download nur für die Zielgruppe). Code-Aufgaben lassen sich mit einem Klick als Java- oder Python-Variante duplizieren; mit hinterlegter KI-Schnittstelle wird die Musterlösung konvertiert (als Vorschlag zu prüfen). Schülerinnen und Schüler sehen ihre Aufgaben als Kacheln mit Status (offen, abgegeben, korrigiert, überfällig), Hinweis auf die nächste Abgabe, Materialliste und ToDos, und filtern nach Themengebiet, Typ und Status.
- **Wiki:** Lehrkräfte legen Nachschlage-Seiten zu Fachbegriffen und Konzepten an (einfache Markdown-Formatierung: Überschriften, Listen, fett, kursiv, Code). Seiten sind ab der eingestellten Jahrgangsstufe sichtbar; bearbeiten und löschen kann sie die erstellende Lehrkraft (Admin alle). Beim Einrichten legt der Migrator automatisch eine ausführliche Anleitung für Lehrkräfte plus Beispiel-Seiten an, die den Stufen-Filter zeigen.
- **Präsentationen:** Lehrkräfte stellen Präsentationen aus Text- und Code-Folien zusammen (Java, Python, SQL, HTML). Der Präsentationsmodus bietet Vollbild (Taste F), Navigation mit Pfeiltasten und Syntax-Highlighting für Code-Folien; Code lässt sich direkt in der Präsentation verändern und speichern, um live zu demonstrieren. Stufen-Filter wie im Wiki. Die Übersicht ist kompakt: pro Jahrgangsstufe eine Zeile je Präsentation mit Folienzahl, Themen-Link und den Knöpfen *Präsentieren*, *Moderator* (nur Lehrkräfte), *Bearbeiten* und *Löschen*. Startpakete für die Klassen 6 bis 10: Die **Informatik-Jahr-Decks** (Jgst. 9 und 10, importiert aus dem Schulwebsite-Projekt) stimmen aufs Schuljahr ein - ohne Übung; die **Themenpräsentationen** vertiefen jeden Lernbereich und enden mit einer Übungsaufgabe samt Musterlösung (Jgst. 6: Informationen darstellen, gut präsentieren; Jgst. 7: Hypertext und Internet, digitale Kommunikation, Algorithmen mit Java-Demos; Jgst. 9: funktionale Modellierung, Tabellenkalkulation, Datenmodellierung, SQL, Java-OO, Datenschutz; Jgst. 10: Java-Wiederholung, verknüpfte Tabellen mit JOIN, Arrays, Datenkapselung, Polymorphismus, Projekt, Datenbanken in Java). Jede Seed-Präsentation hat einen permanenten Themen-Link (/praesentationen/thema/{slug}), und die Wiki-Seite *Präsentationen: Themenübersicht* listet alle Themen mit Links. Über eine Seed-Versionsspalte (seed_version) werden Startpakete des Admins bei einem Migration-Lauf auf den neuesten Folienstand gebracht - von Lehrkräften bearbeitete eigene Präsentationen werden nie überschrieben; dabei werden auch alte Zeilenumbruch-Notizen in Code-Folien bereinigt. Der **Moderatorenbildschirm** (/praesentationen/{id}/moderator, nur für Lehrkräfte) zeigt aktuelle und nächste Folie, eine klickbare Folienliste, Timer und Uhr und läuft im selben Browser synchron mit dem Präsentationsfenster auf dem Beamer (BroadcastChannel).
- **Quiz-Arena:** Quiz mit vier Antworten pro Frage anlegen, an Klassen oder Einzelne austellen. Spielen mit sofortigem Feedback, Bestwertungen und Ergebnisliste für Lehrkräfte.
- **Prüfungsmodus:** Prüfungen und Schularbeiten mit Gruppen und einer Vorlage pro Gruppe, Teilaufgaben mit BE und Musterlösung. Während der Prüfung sind für Teilnehmende alle anderen Bereiche gesperrt (Server-Umleitung und reduzierte Oberfläche), Eingaben speichern automatisch. Korrektur manuell oder anonymisiert per API; Vorschläge müssen gegengeprüft werden. Nach der Herausgabe: Punkte, Note, Feedback und der Vergleich eigene Lösung vs. Musterlösung.
- **Diagramme:** Klassendiagramme selbst zeichnen (Mermaid-Editor mit Live-Vorschau) und jederzeit zwischenspeichern. Automatisch erzeugt InfoCraft Diagramme aus Java- und Python-Skripten (Klassen, Attribute, Methoden, Sichtbarkeiten, Vererbung) und aus den Tabellen einer SQL-Datenbank (Spalten, Primärschlüssel, Fremdschlüssel-Beziehungen). Jedes Diagramm lässt sich als PNG exportieren. Lehrkräfte können das automatische Erzeugen pro Klasse deaktivieren; selbst zeichnen bleibt für Schülerinnen und Schüler immer möglich. Dazu kommen zwei weitere Diagrammtypen mit einer eigenen, Mermaid-ähnlichen Syntax (zeilenbasiert, Schlüsselwörter wie *wenn ... dann ... sonst ... ende*, *solange*, *wiederhole ... bis*, %%-Kommentare): **Struktogramme** (Nassi-Shneiderman) für Algorithmen mit Sequenz, Verzweigung und Schleifen, gerendert als verschachtelte HTML-Boxen mit Bedingungsbalken und wahr/falsch-Spalten; **Datenflussdiagramme** für die funktionale Modellierung mit Quellen, Senken, Prozessen, Datenspeichern und Kantenbeschriftungen, intern nach Mermaid flowchart übersetzt (mit PNG-Export). Fehler in der Quelle werden mit Zeilennummer und Hilfetext angezeigt.
- **Präsentieren-Schalter:** Ansicht per Klick vergrößern (Schriftgröße), nur für Lehrkräfte sichtbar; die Präsentationen haben zusätzlich ihren eigenen Vollbild-Modus.

## Schnellstart (lokal)

```bash
git clone https://github.com/creativecat/infocraft.git
cd infocraft
php tools/migrate.php --driver sqlite
php -S localhost:8080 -t public public/index.php
```

SQLite läuft ohne weiteren Datenbankserver, die Migration erzeugt Schema und Beispieldaten.

## Installation auf Webspace (PHP 8.3+, auch 8.5)

1. Dateien hochladen, DocumentRoot der Domain auf public/ zeigen lassen.
2. config/config.example.php nach config/config.php kopieren und anpassen (Treiber sqlite oder mysql, demo_mode, ggf. SSO, optional exam.api für die anonymisierte API-Korrektur).
3. Einmalig php tools/migrate.php ausführen (Schema + Beispieldaten).
4. Für MySQL: sql/schema.mysql.sql liegt bei, alternativ einfach die Migration laufen lassen.

Ohne Composer, ohne Node-Build: nur PHP mit PDO.

## Prüfungsmodus und API-Korrektur

Prüfungen und Schularbeiten durchlaufen vier Phasen:

1. **Vorbereitung:** Gruppen bilden, pro Gruppe eine Vorlage aus der eigenen Werkstatt wählen, Teilaufgaben mit BE (Bewertungseinheiten) und Musterlösung anlegen.
2. **Durchführung:** Beim Start bekommt jedes Gruppenmitglied eine eigene Arbeitskopie der Vorlage. Bei Prüfungen (nicht bei Schularbeiten) sind alle anderen Bereiche gesperrt: Der Server leitet Teilnehmende auf die Prüfung um, die Navigation ist reduziert. Eingaben speichern automatisch, ein Live-Monitor zeigt der Lehrkraft Beginn und Abgabe.
3. **Korrektur:** Manuell je Arbeit oder mit einem Klick anonymisiert über eine API. Die API sieht nur Pseudonyme (Arbeit A, Arbeit B, ...), nie Namen. Vorschläge zählen erst, wenn die Lehrkraft sie gegengeprüft und gespeichert hat; erst dann kann herausgegeben werden.
4. **Herausgabe:** Schülerinnen und Schüler sehen erreichte BE, Note (Notenschlüssel: ab 92/81/67/50/30 Prozent die Noten 1 bis 5, sonst 6), Feedback der Lehrkraft und den direkten Vergleich zwischen eigener Lösung und Musterlösung. Dasselbe Feedback-Format gilt auch für Schularbeiten ohne Sperre.

Konfiguration der API-Korrektur in config/config.php (optional, siehe config.example.php):

```json
'exam' => [
    'api' => [
        'mode' => 'json',   // json: bewertet direkt, chat: Chat-Endpunkt (OpenAI-kompatibel)
        'url' => 'https://beispiel.example/korrektur',
        'key' => 'token',   // optional, wird als Authorization: Bearer gesendet
        'model' => '...',   // nur für mode chat
    ],
],
```

Anfrage (anonymisiert, ohne Namen):

```json
{
  "exam": {"title": "HTML-Pruefung", "kind": "pruefung"},
  "tasks": [{"position": 1, "be": 4, "sample_solution": "Musterloesung"}],
  "works": [{"pseudonym": "Arbeit A", "answers": [{"position": 1, "answer": "..."}], "material": "Projektinhalt, gekuerzt"}]
}
```

Erwartete Antwort:

```json
{"results": [{"pseudonym": "Arbeit A", "tasks": [{"position": 1, "be": 3.5, "feedback": "Fast perfekt"}]}]}
```
